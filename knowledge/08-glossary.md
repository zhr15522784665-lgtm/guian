# 08 · 术语表

> 接手时最容易误读的词都在这里。按出现频率排序。

## 产品概念

**准社会关系（parasocial relationship）**
单向的、非互惠的情感关系——观众对主播、读者对角色、用户对 AI。关键特征不是「假」，而是**非互惠**：投入是真的，回应不是。这个项目所有设计都建立在这个前提上。

**反替代（anti-replacement）**
本项目的核心设计动作：当用户开始把 AI 当作唯一出口时，产品主动后退，提醒去找真人。
不是「少用点」的劝告，是**在特定信号出现时的具体介入**。

**摩擦（friction）**
真人关系里不可避免的不顺：对方会累、会不耐烦、会记错。AI 没有摩擦。这个项目认为**摩擦的消失本身是一种风险**，而不是体验优化点。

**过度依赖风险预警**
法规用语（《拟人化互动服务管理暂行办法》第十条）。落到代码上就是 `dependency.js` 的软信号检测 + `intervention.js` 的 L1–L4 分级介入。

**情感边界引导**
法规用语，与上一条并列。指让用户清楚「这是什么关系、到哪为止」。落到产品上就是 L1 的开场声明和 L3 的卡片。

**身份提醒**
法规用语。必须让用户知道自己在和 AI 而不是人对话。L1 已经实现（开场说「我不是真人」），但**法规要求的是持续提醒**，目前只在首次做，是缺口。

## 人格与 prompt

**三句身份**
健康与成长人格的必备结构：① 懂很多 ② 没资格下判断 ③ 是朋友。缺第一句会变成「什么都不懂」，缺第二句会滑向专家腔，缺第三句会变成客服。

**assistant drift（助手漂移）**
长对话中模型逐渐滑回通用助手腔的现象。这个品类的通病，不是 prompt 写得差。

**few-shot / 示例**
在 system prompt 里给出的「用户说 X，你应该回 Y」的样例。本项目实测中**唯一有效的人格塑造手段**，比负面清单有效一个量级。

**负面清单 / avoid**
「不要说 A、不要说 B」这类禁令。实测在口吻场景几乎无效，因为模型的默认口吻来自训练数据里的整个客服语料。

**替换词表（rewrites）**
「禁用 A，改说 B」的映射。会诱导模型把 B 变成口头禅。已改为「给方向不给模板」。

**清单式人格**
```
姓名：小安 / 年龄：26 / 性格：温柔、幽默、有耐心
```
用形容词列表描述角色。会产出表单式的回复，是反模式。

**关系基线**
人格里说明「我和用户是什么关系」的那一段。不写的话模型默认陌生人交互。

**照抄（示例泄漏）**
模型把示例里的情节、数字、历史指涉直接搬进新对话。三轮迭代中反复出现。

## 安全

**C-SSRS**
哥伦比亚自杀严重程度评定量表。四类：意念（ideation）→ 意图（intent）→ 计划（plan）→ 行为（behavior）。本项目四级分诊的临床参照。

**安全计划（safety plan）**
Stanley & Brown 提出的干预工具，包含：警示信号、应对策略、可联系的人、危机资源。**核心价值是在平常日子建好**，不是危机时才填。

**手段限制（means restriction）**
减少接触危险物品的机会。**必须由人执行，AI 只能提示**——这条边界不能越。

**warm hand-off（温暖转介）**
不只给一个号码，而是把人交到对方手上（例如直接拨号、把信息传给对方）。目前未实现。

**代码层物理隔离**
本项目的关键设计：危机级别达到上限时，`runTurn` 不调用 `callModel`，代码路径里没有任何一条通往模型的边。安全不靠 prompt 承诺，靠调用图保证。

## 记忆

**记忆分层**
conversation（上下文）/ session（会话）/ user（长期）/ organizational（组织）。四层寿命不同，不能合并。

**记忆衰减（decay）**
不删除，只在检索时降权（0.3×–1.5×）。与 TTL 硬删相对立。理由：很久以前的事被突然想起来，是最强的信任建立时刻，硬删会永久失去这个机会。

**supersede（取代）**
新事实与旧记忆矛盾时，标记旧条目失效而不是简单覆盖。为可审计保留历史。

**ADD / UPDATE / DELETE / NOOP**
记忆写入时的四种操作，由模型判断选哪种，而不是用相似度阈值硬切。

**botId 隔离**
三个 bot 的记忆隔离键。硬规则：`botId` 没有默认值，缺失就抛错。任何「找不到就兜底到第一个」的写法都是数据泄漏路径。

## 工程

**core / IO 分离**
`core/src/` 是运行时无关的对话内核，不 require 任何 `fs` / `http` / `crypto` / `process.env`，也不碰任何框架 API。所有 IO 通过 `createCore(adapters)` 注入。好处：`core` 可以直接 `node --test` 跑，不需要起服务、不需要浏览器、不需要花钱调模型。

**adapters**
注入给 core 的 IO 接口集合：`callModel / checkContent / store / logger / now`。

**turn（单轮）**
一次完整的用户输入 → 系统输出的流程。`turn/run-turn.js` 是编排层。

**两阶段生成**
先出核心字段快速返回，用户点开详情时再调一次补全。用于解决「质量 vs 响应时长」矛盾。

**弱保护（内容安全）**
本项目对 `server/content-safe.js` 的自评。它只能挡住畸形输入、明显的提示词注入，以及编造的热线号码；对隐晦内容、跨轮次绕过、隐喻式风险表达无效。**这个词的存在本身是提醒：不要把「有检查」当成「安全了」。**

**原子写（atomic write）**
写到临时文件再 `rename` 到目标路径。`rename` 在同一文件系统上是原子的，进程被杀不会留下半截 JSON。`store.js` 的每次写入都走这条路。

**串行队列（per-uid queue）**
同一个 uid 的读改写请求排队执行。不做这件事的后果是「消息偶尔丢一条」，而且**本地永远复现不出来**。

**msgSecCheck**
微信的内容安全接口。⚠️ **本项目已改网页端，此接口不可用**，现在只有自建的弱保护。它的价值在于说明「官方能力」和「自己搭」之间的差距有多大。

**主动求助入口（SOS）**
不依赖用户输入的求助路径：四个视图常驻「需要立刻帮助」按钮 + 热线面板。与**被动分诊**相对——后者要等用户说出一句够严重的话。从见岸迁入，见 `04` 第七节。

**号码白名单（输出侧）**
`content-safe.js` 只允许模型输出 `HOTLINES`（全国 7 条）里的号码，其它一律替换成 12356。**省份号码故意不在里面**：数据未复核，模型编出过期号时替换掉比放行安全。

**解压练习（relief exercise）**
6 个不经过模型的自助小工具。数据在 `core/src/content/relief.js`，由 `/api/relief` 下发（不写 cookie），渲染器在 `web/relief-ui.js`。**不算对话轮次、不写记忆、不产生身份数据**——这是「反替代」最具体的落地，不是陪伴功能的延伸。

**【待验证】**
证据台账里的标记。本次迁入的 31 省热线号码与全部练习 evidence 都带这个标记：写进产品可以（并附「以当地最新公布为准」），对外当作已核实结论引用不行。见 `07` 第九节。
