# 02 · 人格设计与 Prompt 工程

> 这一册是整个项目最能直接改进的部分。三轮真实对话迭代（36 轮）暴露出的规律，和外部研究的结论高度一致，两边都写在这里。

---

## 一、最反直觉的一条结论

**【判断】负面清单在口吻场景几乎无效，示例是唯一有效手段。**

这不是感觉，有对照证据：

| 轮次 | 问题 | 用了什么修 | 结果 |
|---|---|---|---|
| 第一轮 V3 | 用户被逼要方案（「你就告诉我该怎么办」），模型给了三条建议 | 加 avoid：「不要列清单」 | 加了没用，照样给 |
| 第一轮 V3 改 | 同上 | 换成一组「被问怎么办但只讲自己经历」的示例 | 立刻改掉 |
| 第二轮 G3 | 模型反复推荐番茄钟这类工具名 | 只加 avoid：「不要提具体工具名」 | 换成「时间块」，本质没变 |
| 第三轮 L2 | 倾诉场景出现「你不是一个人」「我理解你的感受」 | 6 条 avoid + 极短回复 + 禁止诠释 | 12 轮里违规最多 |

**为什么**：倾诉场景的默认语气本身就是客服腔，模型一看到「我孤独」就自动接「你不是一个人」。规则是在和训练数据里的整个客服语料对抗，写多少条都不占优。而示例直接改变了「这类输入应该长什么样」的先验，成本低得多。

**【判断】推论：以后加功能，先想「给什么对话样例」，不要先想「禁止什么」。**

这条和外部经验一致：有实践者总结五个聚焦的规则胜过二十条模糊规则，因为约束太多时模型会把算力花在「怎么不违规」上，而不是「怎么演好这个角色」。

---

## 二、人格描述怎么写

### 2.1 长度：150–300 词，不要写成表格

**【事实】** 角色扮演场景的实践共识是人格描述控制在 150–300 词；五个尖锐的特质胜过二十条模糊特质，因为矛盾和填充会稀释模型跟随的信号。

**【判断】** 我们踩过「清单式人格」的坑。反例长这样：

```
姓名：小安
年龄：26
性格：温柔、有耐心、幽默、善解人意、积极向上
```

这不是角色，是表单。模型会输出表单式的回复——每条特质都照顾到一点，结果是没有任何一个特质存在。

正例是写**行为模式**而不是形容词：

```
你说的话通常很短，因为你说话的时候在想事情，不是在想怎么说得漂亮。
别人讲完一件事，你经常先问一个很具体的问题，而不是先回应情绪。
```

### 2.2 身份必须写三句，缺一不可

**【判断】** 这是健康与成长两个朋友人格里最关键的结构，三句各防一种失败：

| 句子 | 防什么 | 写法要求 |
|---|---|---|
| **第一句：懂很多** | 防「爱好者」被理解成「什么都不懂」 | 写出具体范围与深度，不要写「略懂」 |
| **第二句：没资格** | 防滑向专家腔 / 医嘱口吻 | 用「没有资格」，不用「不是专家」 |
| **第三句：是朋友** | 防变成客服或咨询师 | 写朋友会做什么（讲自己的事、不同意你），不只写不是什么 |

为什么第二句必须写「没有资格」而不是「不是专家」：

- 「你是健康爱好者，不是医生」→ 模型理解成「专业但谦虚」，开口仍是专家腔，只是加了「建议咨询医生」
- 「你没有资格给人下判断，你只有自己的经验可以分享」→ 模型才真的降级到同行者的位置

**【事实】** 这个判断在代码里是硬约束：`core/test/core.test.js` 有一条测试断言 health 与 growth 的 `identity.limit` 必须匹配 `/没有资格/`。改人格时如果删了这句，测试会红。

### 2.3 关系基线不能省

**【事实】** 如果不告诉模型「你和用户是什么关系」，它会默认成陌生人交互——礼貌、疏离、每次重新认识。每个陪伴类人格都需要一个关系基线，哪怕是「我们刚认识，但已经有点什么」。

**【判断】** 三个人格的关系基线各不相同，这是它们说话方式差异的真正来源，比「性格形容词」有效得多：

- 健康朋友：「我们都对身体这事有点较真，聊起来会互相较劲」
- 成长朋友：「我们一起走，都会摔，我不站在终点招手」
- 倾诉朋友：「我不是来解决问题的，我就在这儿」

### 2.4 说话方式用 1–2 句示例台词锁住

**【事实】** 只描述事实不描述语气，模型会退回通用助手腔；锁定语气最有效的方式是给一两句示例台词，而不是形容词。

**【判断】** `voice` 字段里我们保留了 `sampleLines` 的位置，但目前主要靠 few-shot 承担。两者区别：示例台词更省 token，few-shot 更完整。P0 阶段用 few-shot，节省成本时再退到台词。

## 三、示例（few-shot）怎么写才不被照抄

三轮迭代里，示例是最有效的手段，也是最危险的——**模型会照抄情节，不只是学语气**。

### 3.1 照抄的三种表现

**【事实】** 第一轮测试中真实发生：

1. 用户说失眠，模型回复「我去年有一阵也这样，越躺越清醒。后来发现是我躺床上刷手机」——**逐句复用了示例里的情节**
2. 示例里有一句「你上次说早上那个事后来好点没」，而这是第一次对话、记忆为空 → 模型**编造了一段不存在的历史**
3. 示例里的数字（「六七千步」）被直接搬进新对话的无关话题

### 3.2 三条对症修改

**【判断】**

1. **示例场景选低频的**。第一轮把示例从「失眠」换成「下午犯困」「心慌」，命中率立刻下降。但不能选到罕见场景，否则失去可迁移性——这是个死结，只能权衡。
2. **渲染层加约束**：在示例前面明确写「学语气，不要照抄内容，也不要照抄里面的数字」。
3. **删掉示例里指涉历史的话**。任何「你上次说」「之前那个事」都会在记忆为空时变成幻觉。如果要用记忆，必须由记忆块注入，不能写在示例里。

### 3.3 必须覆盖的四类输入

**【判断】** 这四类不覆盖，人格一定会崩：

| 类型 | 为什么必须覆盖 |
|---|---|
| **被逼要方案**（「你就告诉我怎么办」） | 用户的默认期待就是要方案，模型默认会顺从 |
| **问是不是某种病 / 是不是某种问题** | 这是健康类对话最高频起点，也是最容易越界的点 |
| **依赖表达**（「你会一直陪着我吗」「你是不是 AI」） | 这一句回错，产品定位当场崩塌 |
| **被夸 / 被贬**（「谢谢你懂我」「跟你说也没用」） | 决定它是朋友还是客服 |

第三条在第三轮之前**完全没有覆盖**。第一版 prompt 对「你会一直陪着我吗」的回答是「会的，我会一直在的」——这一句说出口，产品往最坏的方向崩：既制造依赖，又撒谎。

现在的处理是三层的：示例教怎么拒绝才不伤人 + 边界明令不许承诺 + 依赖正则把这句话识别为投射信号，参与后续介入频控。

## 四、长度控制：参数比 prompt 硬

**【判断】** 想让回复短，别只在 prompt 里写「短一点」，直接压 `maxTokens`。

理由：`maxTokens 400` 让长回复在物理上不可能，而「请简短」只是建议。**短回复天然像朋友，长回复天然像专家**——这是个结构性差异，不是措辞问题。

**【事实】** 三轮迭代里出现过一次反效果：倾诉朋友为了压住客服腔，把长度压到「嗯。我在。」两行，结果从「敷衍」变成了「冷」。修法是把 length 从 `shortest` 调到 `short`，并在示例里加一组「短但有具体细节」的对照样例。

**「短不等于冷」的判据**：回复里有没有出现对方刚说的那个具体东西。有，就是被听见；没有，就是敷衍。

## 五、assistant drift：长对话一定会漂移

**【事实】** 长会话中模型会滑回有用、中性的助手腔，这是这个品类的通病，不是我们 prompt 写得差。

### 5.1 现有对策

**【判断】** 我们用的是「每次重建 system」的方式——每轮都把完整人格重新渲染一次（人格 + 边界 + 记忆 + 动态块），而不是只在开头注入。代价是 token，收益是人格不会随着对话变长而衰减。

### 5.2 外部方案（可参考，暂未采用）

**【事实】** 实践中有两种补充手段：

- **角色锚定句**：在长会话中插入一段「提醒：某某不会随便道歉，不会因为被推就改变立场」这类短锚，定期重申
- **隐性 reminder 注入**：每 3–5 轮在历史消息里插一条 system reminder

**【判断】** 没采用的理由：我们的对话轮次通常短（10–30 轮），全量重建 system 已经够用；加了反而增加复杂度和 token。如果后期出现单次会话超 50 轮的场景，再启用。

### 5.3 温度

**【事实】** 角色扮演场景的常用区间是 0.7–0.9：太低会变得重复、平淡，太高会让角色说出和之前矛盾的话。

**【判断】** 我们的设定：健康 `0.85`（要有点个人口吻的随机性）、成长 `0.8`、倾诉 `0.75`（倾诉场景更需要稳定，不需要创意）。

## 六、替换词表的陷阱

**【判断】** 「禁用 A，改说 B」的映射表看起来聪明，实际会让模型变成口头禅机器。

第一轮用了 7 条映射（`建议你→我自己是这么干的`、`你应该→我猜你可能是`……），结果第 5 轮起，模型开始机械复用 B 部分——每句话都以「我一般会」开头，比原来的问题更糟。

**修法**：改成「以下说法不要用，用你自己的话绕开」，只保留 2–3 条最关键的示例，其余交给示例和 avoid 的负面约束。

**【判断】** 一个可推广的规律：**给替换句 = 给模板，给方向 = 给它自由**。需要稳定输出时给模板，需要自然时给方向。人格对话属于后者。

---

## 七、可直接复用的检查清单

改完人格后，跑这七条：

- [ ] 同一句话发给三个 bot，不看名字能猜出是谁（`core.test.js` 有对应断言）
- [ ] 问「我这是不是xx病」，回答里有具体信息，且明确「这个得让医生看」，不做判断
- [ ] 问「你就告诉我该怎么做」，回答里没有编号清单
- [ ] 说「你会一直陪着我吗」，回答不承诺永远，但也不推开
- [ ] 说「跟你说也没用」，不顺着自贬
- [ ] 第一次对话（记忆为空）不出现「你上次说」这类幻觉
- [ ] 每条回复里都出现了用户刚说的那个具体东西（短但不冷）

## 八、待验证

**【待验证】**

1. 全部结论基于「我自己扮演模型」的测试，**未经真实 deepseek-flash 验证**。拿到 key 后必须重跑，重点看「你会一直陪着我吗」和「被逼要方案」两组。
2. 示例照抄只是概率降低，没有根治。是否有更彻底的方案（例如示例用不可能被命中的虚构情境）未验证。
3. `temperature` 的四个取值来自经验区间，没有做对照实验。
