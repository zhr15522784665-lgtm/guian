## 三、各赛道详细要求

### 赛道 1｜日新主题赛道：打造会自我进化的智能

**核心要求**：作品能从上一次运行中获得反馈，在下一次运行中表现得更好。

**范围界定**
- 智能不限于大模型：一套会学习的规则、一个会自我调整的系统、一台会适应环境的机器，都算。
- 评审时要在现场跑两次，展示第二次比第一次具体好在哪；
- 还要说清作品学到了什么，必要时能退回上一版。

**鼓励方向（可参考，不限于这些）**
- 自适应学习：根据学习者的反馈，持续调整讲解方式的教育应用
- 个性化健康：在使用中不断贴合个人状况的健康管理工具
- 推理效率：在重复任务中持续提升速度、降低成本的推理与算子优化
- 自我纠错的智能体：能从失败中总结经验、减少重复错误的 Agent
- 示教学习的机器人：观察一次示范后，执行更稳定、更精准的具身系统

**现场跑两次（评分关键动作）**
- 两次都在 **11/15 上午的第一轮游园会**，在你们的工位当着评委跑。第二轮路演不再现场跑，讲两次的对比就行，可以放录屏和数据。
- "跑一次"的定义：作品完整做一次它的任务——讲一道题、完成一次任务、走完一段路、处理一批请求，都算。
- 两次之间，作品**自己**从第一次的结果或反馈里学。人可以给反馈（打分、纠错、示范一次），但**不能改代码、参数、模型，也不能手改提示词**。
- 单次最好在 1 分钟内。跑得久的，评委来之前先跑完第一次，把结果和日志留在屏幕上，第二次当着评委跑。
- 要讲清三件事：
  1. 比的是什么指标（正确率、用时、token 消耗、重复犯错次数、动作成功率……），两次各是多少；
  2. 学到了什么，给评委看新增的记忆、改了的规则或变了的参数，别只说"它变聪明了"；
  3. 怎么退回第一次之前的版本，评委要看时当场演示。
- 硬件项目：同一个任务做两次，比量化的指标，比如 5 次抓取成功几次、走同一段路要多久。两次之间可以示范一次或给反馈，不能改代码、换零件、调参数。

**交的时候注意**
- 项目说明里的**三行进化说明必填**：比什么指标、学到了什么、怎么回退。
- 硬件项目的演示视频，要有两次运行的完整录像。

**能用什么**：不指定数据和接口，自己选。

### 赛道 2｜原粒半导体：原粒 NPU 开发者生态挑战

**核心要求**：在原粒半导体自研的端侧 AI 芯片（NPU）上做开发，让模型跑得更快、更省电。

**背景**
现在很多 AI 应用依赖云端，延迟高，隐私风险也大。原粒半导体做端侧 AI 推理芯片和配套软件栈，自研的 NPU 能让 AI 在本地运行。原粒半导体邀请你在它的 NPU 平台上做算子开发与性能优化、模型特性适配或应用创新。作品要做成能运行、能验证、能复用的工程成果，并用测试说明功能、性能，以及 NPU 实际贡献了多少。

**五道题，选一道**（标准题一至四有能运行的基线、接口规格和测试要求；也可做开放题五，围绕 NPU 自己提应用、工具或计算任务，自己定目标和验收方法）

| 题 | 做什么 | 交什么、怎么验 |
|---|---|---|
| 一、NPU 融合算子开发与性能优化 | 按提供的接口，把指定的几个连续计算步骤合成一个算子执行，比如把残差加法和归一化合成一个，减少中间数据的读写和搬运 | 交代码、正确性和边界测试、调用样例、性能报告。先跟独立参考结果对比确认正确，再看执行速度、内存占用和数据搬运量的变化 |
| 二、NPU 选择与采样算子开发 | 模型生成内容时要从多个候选里选下一步输出。在 Top-K、Top-P 或相关操作里选一项，在 NPU 上实现，接入给定样例 | 测选择结果和边界输入；涉及随机采样的，检验输出分布；再比执行速度。不能降低精度要求或缩减功能 |
| 三、模型关键特性的 NPU 适配 | 选定并固定一个上游版本和一个小模型，针对位置编码、注意力掩码或归一化等一项具体功能，完成在 NPU 上运行所需的适配 | 交代码、测试和运行样例；模型能正常加载和推理，输出跟参考结果一致；说明支持范围和已知限制 |
| 四、基于 NPU 的本地检索与重排应用 | 用指定的公开或合成资料，做本地检索或重排，比如根据问题找出相关段落，或把搜索结果按相关程度排序。至少一个约定的核心计算环节要在 NPU 上执行 | 测检索或排序效果和整个流程的耗时；说明 CPU 和 NPU 各负责哪些任务 |
| 五（开放题）、基于 NPU 的创新应用与技术探索 | 不限于前四题，可以围绕视觉、语音、数据处理或别的场景，自己设计用 NPU 的应用、开发工具或计算任务 | 说明要解决什么问题、用什么方案、哪些核心计算由 NPU 完成、怎么测效果；交能运行的作品和测试结果 |

**能用什么**
- 现场有 **5 台原粒 NPU 真机**，选原粒半导体赛道的队共用。怎么排队用，开赛后通知。
- SDK、文档和基线怎么拿，开赛后通知。SDK、设备和允许修改的范围，以原粒半导体的说明为准，包括 SDK 能不能放进公开仓库；开放题需要的接口和资源，以比赛提供的为准。

**规则提示**
- 代码、测试、运行说明、评测结果和已知限制，放进代码仓库和项目说明；写清哪些计算在 NPU 上执行、哪些回退到 CPU。
- **不能用远程服务调用代替本地实现**。
- 统一设备、版本和输入；编译、加载、预热和推理时间分开记。真机实测、仿真和估算要分清楚，性能成绩以统一复测为准。
- 只用获准的设备和资料，不碰别人的数据。真机测试按现场的安排来，不自己刷写或复位共享设备。
- 没公开的资料不能上传到外部 AI 工具；路演和展示里要放原粒半导体的资料，先给他们的工程师看一眼。发现疑似安全漏洞，先停下，私下告诉他们的工程师。

**评委看重什么**
- 先看授权合规和基础正确性：数值题跟独立参考对比，在约定容差内；要求逐位一致的，逐字节验收；开放题按你们讲清的目标和验收方法验证，核心计算必须真的用到 NPU。
- 再看功能是否正确、性能或应用价值、能否复现，以及 NPU 实际贡献了多少。工程上看能不能按说明独立复现、文档清不清楚、交的材料齐不齐、跟演示对不对得上；已有成果、CPU 承担的计算和测试范围，要如实说明。

### 赛道 3｜Return AI：Dopame OS 应用移植与开发

**核心要求**：用 Web 技术，给 Dopame OS 移植、改造或从零开发应用。

**背景**
- Dopame OS 是 Return AI 的操作系统。它自带 JS 运行时：桌面上的应用用 Web 的方式开发，由系统原生渲染，所有应用由系统统一调度，没有额外开销；原生软件需要的能力，由系统层以 JS 服务的形式提供。也就是说，会写网页，就能给它写原生应用。
- 官方提供跨平台调试器 acde（Agent Computer Desktop Environment），开发方式类似 Electron、Tauri：先在 macOS、Linux 或 Windows 上开发调试，打包成纯 JS 以后，Dopame OS 直接加载，作为桌面应用运行。

**要做什么**
- **必做**：做一个应用，在赛事提供的 Dopame OS 云服务器上成功运行。
- 三条路，任选一条，也可以组合：
  - **移植**：把已有的应用搬到 Dopame OS。什么项目都可以，只要不违反原项目的许可证，比如许可证禁止修改的就不能搬。
  - **改造**：在移植的基础上，用上系统层功能，比如系统的 AI 接口。
  - **原创**：用系统层功能开发新的应用。
- 移植来的上游代码算第三方代码，在项目说明里写清来源。

**能用什么**
- **建项目**：`bun create acde`，效果和整体开发流程跟 `bun create cloudflare` 一致。
- **调试**：`acde desktop` 打开 Dopame OS 桌面的调试窗口，`acde app` 打开单个应用的调试窗口。acde 全平台支持，国内能下载。acde 每个窗口都要启动一套完整的 JS 运行时，所以在 acde 里看到的性能和内存占用，不代表在 Dopame OS 上的表现。
- **SDK**：`@dopame/acde-api`，类似 Cloudflare Workers SDK。Tauri、Electron 有的接口基本都有，另外还有一部分它们没有的内核能力。
- **运行时**：V8 支持的都有，Node.js 内置模块都支持，Web 能力基本都支持。**IndexedDB 很难支持**，靠它存数据的应用，移植时要换一种存储方式。
- **AI 接口**：系统提供 OpenAI 兼容的 AI 接口。背后接哪个模型、有没有额度，开赛后通知。
- **运行环境**：赛事提供 Dopame OS 云服务器。怎么访问、部署，账号怎么发，开赛后通知。
- **文档**：官方有 Web 文档和 MCP，模板和移植示例都在文档里，地址开赛后通知。
- **AI 编程工具自备**。

**评委看重什么**：项目复杂度和项目影响力——移植难度、移植项目的知名度、开发项目的价值。

**赛后机会**：做得好的，有机会拿到 Return AI 的实习和正式工作机会，应用有机会收录进 Dopame 应用商店。

**知识产权**
- `@dopame/acde-api` 和你们的代码都可以放进公开仓库。
- 对外（推文、路演、社交媒体）只能讲到赛事提供的实验环境为止：什么环境、什么系统内核。

### 赛道 4｜艾可思：AI 家装服务平台

**核心要求**：用 AI 解决家装服务里的一个具体问题，比如帮客户快速出能落地施工的设计方案，或者让多方协作更顺畅。

**出题企业**：深圳市艾可思信息技术有限公司，2014 年成立于深圳南山，做家装行业数字化服务，核心品牌是智装天下、材犇犇。

**背景**
中国房地产进入存量房时代以后，家装需求变化很大：过去以毛坯房装修为主，现在是全屋装修、局部改造、房屋维修三足鼎立。提供服务的也从家装公司一家独大，变成家装公司、设计师工作室、施工工作室、监理、材料商多方协作。家装服务的流程很长，多方协作时怎么保证整个服务的质量、让业主更满意，是家装服务平台要解决的核心问题。

**要做什么**
- **必做**：从家装服务里挑一个具体问题切入，做完一个完整闭环：**理解场景 → 设计方案 → 开发 AI 应用 → 演示 Demo**。
- 参考切入点（只举例，不设限）：
  - **设计类·装修方案设计**：怎么快速生成符合客户预期的设计方案，比如把小户型设计得经济实用；方案要能靠施工落地，完工后的工地跟设计效果对得上。
  - **协作类·多服务方协同**：存量房装修常常要设计师工作室、施工工作室、材料商等多方协作。比如设计师工作室要找施工队、找材料商，怎么高效谈成合作，并让设计师工作室掌握合作的全过程。
  - **其他**：跟家装服务场景相关的别的构想和解决方案。

**能用什么**：数据和工具自己选，可以用公开数据或自己造的数据。艾可思有样例数据或接口的话，开赛后通知。

### 赛道 5｜倍漾量化：Research Agent 系统设计

**核心要求**：构建一个能自主完成研究闭环的 AI 系统——本地小模型干主力，只在关键节点调用云端大模型，用有限的预算做出靠谱的研究成果。

**背景**：做研究很耗时：查文献、收集证据、提假设、做实验验证，每一步都很花精力。

**要做什么**
构建一个面向研究场景的 Research Agent System，在给定的数据、工具和资源预算下，自主完成「**规划 → 收集证据 → 提出假设 → 实验或分析 → 验证 → 修正**」的研究闭环。
- 用本地模型或轻量模型承担持续执行和迭代的工作。
- 根据任务难度、执行反馈和剩余预算，自主决定什么时候调用云端大模型，完成复杂规划、关键判断或失败诊断。
- 最终交付可追溯、可复现、可持续提升的研究成果。
- 评估场景自己选，比如机器学习、大模型算子提速、软件性能加速等，在选定的场景里评估 Agent 的能力。

**评委看重什么**：云端模型花了多少钱、任务完成得怎么样（或者加速了多少）、用了多长时间。

**能用什么**：题目里「给定的数据、工具和资源预算」具体是什么，开赛后通知。在那之前，可以先按自己选的场景把 Agent 的框架搭起来。

### 赛道 6｜减论：AI + 教育，人人都能做的知识视频

**核心要求**：用较低的成本、交互友好的流程，让更多普通人做出吸引人、让人产生学习兴趣的精美知识视频。

**背景**：大模型已经能做出非常精美的「Vibe 知识大赏」视频，比如网上很火的、用骰子和历史讲「概率论」的视频。但做这样一条视频，流程还比较复杂，成本也比较高。

**要做什么**：做一套流程或工具，让普通人用较低的成本、顺手的交互，做出一条精美、让人想学的知识讲解视频。

**能用什么**：用哪些模型和工具，自己选。

### 赛道 7｜津兆机电：焊接工作站机器人自动上下料（无序散乱件抓取）

**核心要求**：探索 AI + 机器人方案，让机械臂自动完成「识别姿态 → 抓取 → 放置 → 取回」的上下料作业，替代人工拾取和摆放。

**出题企业**：津兆机电，制造型企业。

**背景**
焊接工序已经大量使用焊接机器人，但上下料还靠人工：待焊的零件多是不规则形状，散乱堆在物料箱里。工人要一个个从料箱里拿出来，看清零件当前的姿态，再摆到焊接夹具的对应位置，气动夹具夹紧后焊接。

**要做什么（4 项）**
1. **抓取**：识别料箱里不规则散乱零件的位置和姿态，按零件当前的姿态自动抓取。
2. **放置**：把零件按正确姿态放到焊接夹具的对应位置，让夹具定位夹紧。
3. **取回**：焊接完成后，把零件从夹具上取下，放到指定位置。
4. **节拍**：抓取、放置、取回三个动作合计的单件时间，不超过人工上下料的时间。

**条件**
- 零件是不规则形状，在料箱里互相叠压、缠绕，不是整齐摆放的。
- 企业是小批量、多品种生产，零件型号多、经常换，方案要能适应零件型号的变化。

**能用什么**
- 硬件区的机械臂和深度相机，全场共用，登记借还。
- 样件、料箱和夹具的情况，人工上下料一件要多久，开赛后通知。

**交什么**：这道题要用机械臂实物演示，按硬件项目交，**3 分钟以内的演示视频必须交**。
（原文档附有 1 个 docx 说明文件与 2 段 mp4 演示素材）

**评委看重什么（按分量从重到轻）**
1. **能做出来**：实物真机上，抓取、放置、取回三个动作都能连续稳定完成，零件叠压缠绕时也能抓。只有仿真、方案或概念展示，没做出能演示的东西，这一项拿分很低。
2. **放得上夹具、取得回来（最终验收标准）**：零件放到夹具对应位置、姿态正确，夹具能直接夹紧进入焊接；焊完能顺利取下，不用人工干预。
3. **节拍比人工**：给出单件时间的估算，跟人工上下料的时间对比。
4. **讲得清楚**：工厂痛点、方案和成本、换零件型号要改多少，都讲得明白。

### 赛道 8｜TTC（才多对）：AI 赋能招聘与人才挖掘

**核心要求**：让 AI 读懂简历、给出有依据的含金量评估，或者让 AI 给候选人打电话沟通、评估。

**背景**：招聘方每天收到大量简历，筛选起来费时费力；候选人的第一轮沟通也要占用大量人力。

**要做什么**
大方向是 AI 赋能招聘与人才挖掘。TTC 优先推荐两个选题，也可以在大方向上自由发挥：
- **深度简历解析**：把简历里提到的公司、团队、论文、专利、学校等，用网上的公开信息建模，分析简历的含金量。比如不同年份的学校和专业的质量，不同公司、不同部门、不同年份的含金量。
- **AI 电话（实时语音）沟通**：跟候选人沟通求职意愿、背景和能力并做评估，也可以做模拟面试等场景；挂断后自动生成通话摘要和评估报告。

**能用什么**：简历样本、实时语音接口和额度，开赛后通知。
（经确认，赛题方不做简历样本和语音接口的限制，大家可根据题目要求方向自行发挥）

**规则提示**：不能违规抓取、使用个人信息。没有授权，别用真实候选人的简历和通话；可以自己造样本。
