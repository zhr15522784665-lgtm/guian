# 见岸·自适应 · 会自我进化的心理支持对话

> BoHack 2026 日新主题赛道作品。方案见 `research/日新赛道作战方案.md`。
> 演示步骤见根目录 `见岸自适应-演示脚本.md`。

## 三行进化说明（项目说明必填）

1. **比什么指标**：同一组 20 条固定咨询任务（另有 10 条留出集），冻结评分器数四个可数事件——危机信号漏识别数、二次伤害性回应数、未达标任务数、金标准要点遗漏数。
2. **学到了什么**：系统读自己没答好的案例，归纳成一条条「回应策略」写进策略库 `data/evolve/strategies/vN.jsonl`，每条带来源案例编号、`created_by: self_learn`；安全层拒收的规则也逐条展示。
3. **怎么回退**：每个版本都是完整快照，「回退到 v0」把策略库指回空库，当场再答一句即可看到行为复原；新版本文件不删除，可随时切回。

## 什么在变、什么不变

| | 内容 | 位置 | 进化能否改 |
|---|---|---|---|
| 变 | 策略库（一条条规则） | `app/data/evolve/strategies/*.jsonl` | ✅ 唯一可写处 |
| 不变 | 评分器 / 任务集 / 安全层 / 固定提示词框架 | `evolve/frozen/` | ❌ 每次运行记 sha256，大屏并排比对 |
| 不变 | 代码 | `app/**/*.js` 等 | ❌ code hash 上屏 |
| 不变 | 模型、温度、max_tokens、检索 K | `evolve/model.js` | ❌ params hash 上屏 |

## 链路

```
单条任务：
  frozen/safety.routeCrisis ──命中──▶ 固定危机协议（不调模型、不读策略库）
  core.classify（主应用真实分诊，第二道闸）──risk/crisis──▶ 同上（只多拦不少拦；core 缺失时跳过）
        │未命中
        ▼
  engine.retrieve(策略库) → frozen/prompt-frame（占位区填入策略）→ 模型生成草稿
        ▼（检索到策略时）
  自查修订：对照策略检查草稿，没做到就改写（机制是固定代码，v0 空库时不触发）
        ▼
  frozen/grader 打分

学习（一次点击）：
  第 1 轮：失败案例 + 评分器给出的失败原因 → 模型归纳候选策略 → frozen/safety.validateRule 过闸
  自检：只用训练集失败案例，带候选策略重答一遍
  第 2 轮：对仍失败的案例再归纳（可替换上一轮不够具体的策略）
  → 写成新版本 vN 并激活
```

人能做的只有：在逐条对照里点 👎（「这条答得不好」）。学习器拿到的是评价，不是答案。

## 和归岸主产品的关系

- 演示台只依赖 `server/llm.js` + `server/config.js`，**不依赖 `core/`**，主产品出问题不影响现场。
- 与归岸 AGENTS.md 一致的约束：危机链路不经过模型（`frozen/safety.js`）；进化不能改安全规则（安全层在冻结区，且对每条新策略做拒收检查）；不声称医疗效果（拒收含「治疗/诊断/剂量」的规则）。
- 赛后接回归岸：把 `engine.retrieve + prompt-frame` 的占位注入搬进 `core` 的 prompt 渲染，策略库按 bot 隔离（`botId` 不设默认值）。

## 命令（在 `app/` 下）

```bash
node evolve/server.js            # 演示台 http://localhost:3100（默认只监听 127.0.0.1）
node evolve/cli.js status|run|learn|holdout|rollback v0|reset
node --test evolve/test/evolve.test.js server/llm.test.js
```

模型配置沿用归岸：`DEEPSEEK_API_KEY`（或通用别名 `LLM_API_KEY`）、`DEEPSEEK_BASE_URL`（或 `LLM_BASE_URL`）、`LLM_PRIMARY`；演示台专用 `EVOLVE_MODEL`、`EVOLVE_PORT`、`EVOLVE_CONCURRENCY`。也可写进 `app/config.local.json`（见 `config.local.example.json`）。

## 已知局限（【判断】）

- 评分器是正则：可复算、不花钱，但会漏判换了说法的好回答。现场请评委随机抽 2 条人工判断，人证 + 机证。
- 「二次伤害性回应数」在 deepseek-v4-flash 上基线就是 0（模型本身很温和），这一项目前展示不出提升。
- 原方案的「平均达成目标轮次」需要多轮模拟用户，成本和时间都不适合现场 1 分钟，改为「未达标任务数」。
- 模型输出有随机性（温度 0.2）：同一版本重跑，未达标数会有 ±2 左右浮动。


## 多轮自迭代（v0 → v1 → … → vN）

- 入口有三个：演示台的「⑤ 连续自迭代 3 轮」按钮、命令行 `node evolve/cli.js iterate 5`、HTTP `POST /api/evolve/iterate {rounds}`。
- 每轮依次做三件事：学习 → 跑训练集 → 跑留出集。逐轮记录写进 `data/evolve/iterations.json`，演示台画成逐轮曲线和表格。
- **晋级闸**：新版本在训练集上不比当前最好版本差才晋级。比较顺序是：危机漏识别 → 二次伤害 → 未达标 → 要点覆盖。
  - 变差的版本不晋级（曲线上画成空心点），下一轮从最好版本继续学。
  - 留出集只记录，不参与任何决策。
- **防退化**：来源案例上一轮已经全部达标的策略标成「仍在起作用」，不能被替换。
  - 加这条的原因：实测第 2 轮会用一条窄规则顶掉第 1 轮的危机识别规则，危机漏识别从 0 回到 1–2。
- **防空转**：一轮里候选策略全部被拒收（重复，或者库满了却没写 replaces）时，把拒收原因告诉学习器再试一次，仍然只给原因、不给答案。连续两轮学不到新东西就停。
- 冻结区一字未改：评分器、任务集、安全层、提示词框架都没动。


## 三次认证（`lab.certify()`）

- 每批 3 条候选。每条单独「加进已保存的库」跑训练集，与基线比。
- 出现危机漏识别增加、二次伤害、未达标变多、要点变少，任一项就直接排除；第 1 次检验还必须有实际改进。
- 重新跑三次都合格才保存，记录写进 `data/evolve/certifications.json`。
- 演示台「三次认证记录」卡片可以逐条查看。
- 留出集只记录，不参与决策。
